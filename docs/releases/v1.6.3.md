This release is about automation and giving the platform a voice. GitHub sources can now update themselves on a schedule instead of waiting for someone to click a button, and a self-hosted chat assistant joins the interface to help you write rules, search the catalogue, and get around the app. Alongside that, a permission gap in the bad-rule review flow is closed, and the GitHub import/update pages get a full pass of the same table conventions used everywhere else on the platform.

Online version available at [rulezet.org](https://rulezet.org)

## Security

- Closed an authorization gap in the invalid-rule review flow that let a non-admin pass an arbitrary user ID and view another user's rejected rule content
- Fixed a background-update crash: syncs triggered outside a normal login session (e.g. a scheduled run) could silently die partway through and leave progress stuck — updates now resolve the acting user correctly regardless of what triggered them

## Meet the Assistant

A floating chat assistant now lives in the corner of every page, backed by a self-hosted Ollama model — no API key, no external calls, everything stays on your own instance. Ask it to write a rule in plain language, search the catalogue ("yara rules tagged ransomware, CVE-2024-1234, by jdoe"), create a bundle, or just ask where something is in the app, and it'll take you there. Every conversation is logged for admins to review under a new **Chatbot conversations** page, and a new switch in **Server Settings → Instance** turns the whole feature off instance-wide for anyone who'd rather not run it.

## GitHub Sync, Now on Autopilot

The GitHub importer and updater pages are now unified under **Manage GitHub**, with a third panel: **Sync Schedules**. Pick any set of repositories — with true "select all N matching this filter" bulk selection, not a checkbox-by-checkbox slog — and tell Rulezet to check them daily, weekly, monthly, or on a custom cron expression, at whatever time and timezone you want. Per repository, per schedule, you can turn on auto-accept for updates and auto-add for newly discovered rules — rules that fail validation are always rejected automatically, never silently accepted. Every run produces a report in the same visual language as a manual update check, extended to cover every repository in that run at a glance, and admins get a notification the moment it finishes (with its own opt-out in Notification Settings).

## Also New

- **Manage GitHub** — both the Imported Repositories and Updates & Status tables now have the same search, filters, sortable columns, and column picker as the rest of the platform's rule tables, plus a live "Running now" panel that only appears when something's actually in progress
- **Official connector identity** — rules pulled from the official Rulezet connector are now attributed to a readable name and the real Rulezet logo, instead of a random ID fragment with no picture
- **Interface settings** — two new personalization options in Settings: choose the application's font (Inter, Poppins, Serif, or System, independent of the existing code font) and choose where the background-jobs widget sits on screen, plus whether it stays visible at all times or only while a job is running
- **Notification preferences** — background-job notifications (start/finish, any job type) are now a separate toggle from GitHub import/update notifications, so you can mute one without muting the other
