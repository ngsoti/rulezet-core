This release is anchored by a security pass across every rule format: a Sigma condition-evaluator sandbox escape is closed, and Suricata, YARA, CRS, and Wazuh all gain checks against rules that silently suppress their own detections, backed by new corpus-wide collision and uniqueness enforcement. Alongside that, three new admin systems land — a generalized Task Scheduler, Roles & Permissions, and per-rule Quality Scoring — plus a false-positive validation gate, several account/logging hardening fixes, and a reworked dark mode palette.

Online version available at [rulezet.org](https://rulezet.org)

## Security

- Replaced `eval()` in the Sigma condition evaluator with a restricted AST walk — the previous sandboxed `eval()` did not stop object-introspection escapes (ref A0)
- Suricata rules combining a hash transform (`to_sha256`/`to_md5`/`to_sha1`) with `pass`/`drop`/`bypass` are now rejected outright; plain `pass`/`bypass` usage is flagged as a warning (ref A3)
- YARA rules with a global-rule suppression risk are now flagged (ref A6)
- CRS rules using `ctl:ruleEngine=Off`, `SecMarker`, or `skipAfter` to suppress other rules are now flagged (ref A5)
- Wazuh rules with `overwrite="yes"` (silent rule takeover) are now flagged (ref A7)
- Suricata `flowbit`/`xbit`/`hostbit` values that are unset without a matching set elsewhere are now flagged (ref A2)
- New corpus-wide checks: duplicate identifiers (ref A4/A6/A7), colliding Suricata dataset filenames (ref A1), and colliding `flowbit`/`xbit`/`hostbit` names (ref A2) are now caught across the whole rule set, not just within a single rule
- GitHub update checks now require admin, and symlinked files are rejected during rule import
- Blog SVG attachments are now served with hardened `Content-Type` handling to stop spoofing
- The user detail page's email and admin-status fields are now restricted to the profile's owner or an admin — the old admin-only "Administrator Information" block is removed from the page entirely
- Resend-verification-code is now bound to the caller's own account
- DOMPurify is now constrained to block form-based phishing overlays hidden inside rendered markdown
- Alert emails now escape admin-controlled text, and `notify_emails` is filtered down to valid addresses
- Activity log entries are now attributed to their real actor — self-registration, email verification, and anything run from a background job or worker (GitHub sync, connector pulls, MISP/Velociraptor pushes, bulk ownership transfers) — instead of falling back to "System"

We recommend every self-hosted instance upgrade as soon as possible.

## New: Admin Task Scheduler

A single admin panel now schedules any kind of background job — Similarity, GitHub Import, Field Parser, Quality Score, MISP/taxonomy/galaxy updates, Connector pulls, and more — generalizing the GitHub-only "Sync Schedules" system from a previous release. Tasks are grouped into named workflows, can depend on one another (AND/OR chaining, not just time-based triggers), and are laid out on a custom drag-and-drop DAG canvas with per-run launch history and workflow-level notifications.

## New: Roles & Permissions

Admins can now define custom roles from a growing permission catalog and assign them to users, on top of the existing owner/admin model. A first system role, **Tag manager**, ships pre-seeded and lets its holders tag any rule on the platform, not just their own.

<!-- screenshot: Roles & Permissions page -->

## New: Rule Quality Score

Every rule can now be scored on documentation completeness, traceability, and format-appropriate ATT&CK mapping — deliberately kept separate from votes and favorites, so a well-formed but unpopular rule doesn't get lost next to a popular but undocumented one. Scores appear as a badge on rules, with an admin dashboard to (re)analyze the whole catalogue as a background job.

<!-- screenshot: Rule Quality Score dashboard -->

## New: Rule Validation — a False-Positive Gate

A new Admin/Tag Manager page syncs this instance's rules and scans them against a known-clean binary baseline via `rulezet-validation`, quarantining anything that fires a false positive. Flagged rules feed straight into a runner that lets them be bulk-tagged for follow-up.

<!-- screenshot: Rule Validation runner -->

## Refined Dark Mode

Dark mode's background and cards used to sit too close in value, so surfaces never really separated from one another. The base is deeper now, with real contrast between page background, cards, and highlighted elements — and the harsh violet previously used on MISP Galaxy tags is softer on the eyes.

## Also New

- **Log visibility controls** — Log Definitions get a per-action-type public/private toggle, and individual Activity Log entries can now be flipped public or admin-only too, both with bulk actions
- **Update banner** — admins now see an in-app banner when a newer GitHub release is available, linking to the full releases list
- **Platform tag configuration** — a dedicated management page with backup/restore, more accurate pattern resolution, and default configs now seeded on update as well as on fresh installs
- **Bulk field parser** — new platform-tags detection tab, backed by its own background job
- **Search** — bundle and rule search now match against the original UUID too, shown alongside the ID in results
- **Syntax highlighting** — new highlight.js YARA grammar for CodeViewer/SmartEditor
- **Job logs** now render through the shared AnsiTerminal component
- **Job widget** — free-drag positioning, with your chosen spot remembered
- Fixed a Sigma/GitHub import collision where ATR rules could swallow every `.yml`/`.yaml` Sigma rule in the same batch

## Improvements

- Tag fetching and searching moved server-side for large tag catalogues
- Bulk "import all" jobs for taxonomies/galaxies; fixed a galaxy icon bug
- Shared form label/badge styles consolidated into `core.css`
- Similarity Analysis gained logging, an inline running panel, and database-backed tracking
